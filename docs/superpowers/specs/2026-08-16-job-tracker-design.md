# 岗位清单追踪功能 — 设计文档

## 一、背景与目标

用户有 3 个岗位清单 Excel（`F:\找工作\岗位清单\岗位清单{1,2,3}.xlsx`），合计约 700 条，覆盖私企、编制、考编、考公四类。当前投递靠人工翻 Excel，无法记录进度、无法一键跳转官网。

本功能在 JobFill 扩展中新增一个**岗位清单追踪页**，实现：导入岗位、追踪投递状态、点击直达官网投递。

## 二、需求（已与用户逐条确认）

1. **独立页面**：新标签页（`jobs.html`），不放 popup，不放 options。
2. **导入方式**：由开发侧先把 3 个 xlsx 归一成标准 JSON，插件只读标准 JSON + 支持界面内手动增改岗位。
3. **状态**：六态全流程 —— 待投递 / 已投递 / 已笔试 / 已面试 / 已 offer / 已拒。
4. **截止日期**：每条可记 `deadline`（YYYY-MM-DD，可空），列表按它排序，快到期（≤3 天且状态为「待投递」）标红。

## 三、数据模型

统一 schema，单条岗位记录：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 自动生成唯一 id |
| `category` | enum | `私企` / `编制` / `考编` / `考公` |
| `region` | string | 地区（如「成都」「重庆长寿区」） |
| `position` | string | 岗位名称 |
| `company` | string | 目标单位 |
| `salary` | string | 薪资区间（保留原文，如「9-14」「8.8-13.2」） |
| `competition` | string | 竞争难度 |
| `advantage` | string | 匹配优势 |
| `channel` | string | 投递渠道 / 官方入口（如「BOSS直聘」「四川省人事考试网」） |
| `link` | string | 投递链接 / 直达公告 URL，可为空 |
| `status` | enum | `待投递` / `已投递` / `已笔试` / `已面试` / `已offer` / `已拒` |
| `deadline` | string | `YYYY-MM-DD` 或空 |
| `appliedAt` | string | 投递日期，状态切到「已投递」时自动记录 |
| `note` | string | 备注；xlsx 中未映射的列（工作强度/社交/出差/值班/笔试科目/退役定向/资格提示等）合并于此 |

存储：`chrome.storage.local`，key = `jobList`（数组）。700 条 ≈ 数百 KB，远小于配额。

## 四、页面结构（jobs.html + jobs.js + jobs.css，纯 Vanilla JS，与现有风格一致）

```
┌────────────────────────────────────────────────────────┐
│ 岗位清单   [私企 120][编制 90][待投递 30] ...            │  ← 统计条
│ [导入 JSON] [导出 JSON] [+ 新增岗位]                    │  ← 顶部按钮
├────────────────────────────────────────────────────────┤
│ 筛选：[分类▾][状态▾][地区搜索][关键词搜索]                │
├────────────────────────────────────────────────────────┤
│ 地区 | 分类 | 岗位 | 单位 | 薪资 | 状态▾ | 截止 | 操作    │
│ 成都 | 私企 | 前端 | XX  | 9-14 | 待投递 | 08-20 | 投递/编辑/删 │
│ ...（700 条，简单分页）                                  │
└────────────────────────────────────────────────────────┘
```

交互规则：

- **状态下拉**在表格行内直接切换；切到「已投递」时自动写入 `appliedAt = 今天`。
- **截止日期**快到（≤3 天且 `status === '待投递'`）→ 该行截止日期标红。
- **「投递」按钮**：`link` 非空 → `chrome.tabs.create({ url: link })`；`link` 为空 → 弹提示显示 `channel`（如「渠道：四川省人事考试网」）。
- **编辑/新增**：弹窗（或行内表单）改字段；删除需二次确认。
- **分页**：每页 50 条；筛选/搜索在内存中前端完成。

## 五、数据流

1. 开发侧一次性把 3 个 xlsx 归一为 `岗位清单.json`（统一 schema，`category` 区分四类）。
2. 用户在 jobs.html 点「导入 JSON」→ 文件选择 → FileReader 读取 → 校验 schema → 写入 `chrome.storage.local.jobList`。
3. 手动增改/改状态 → 直接更新 `jobList`。
4. 「导出 JSON」→ 下载 `jobList` 备份。

## 六、入口

- `popup.html` 新增「📋 岗位清单」按钮 → 打开 `jobs.html`。
- `options.html` 可选加一个入口（非必需）。

## 七、边界与错误处理

- **链接为空**：不报错，降级显示渠道名。
- **截止日期为空/格式非法**：不参与排序与标红。
- **导入 JSON 非法**：校验失败时提示错误，不覆盖现有数据（先解析成功才写入）。
- **大列表**：700 条前端筛选 + 分页，无需虚拟滚动。
